# rayfund-bot

Прототип чат-бота поддержки для сайта фонда «РЭЙ» (rayfund.ru). Бот отвечает на частые вопросы по готовой базе тем, без генерации текста и без внешних API. Все сообщения сохраняются на сервере, их можно посмотреть в журнале.

Состав:

- бэкенд на FastAPI (`/api/chat`);
- поиск ответа по `intents.yaml` (char-ngram TF-IDF, без нейросетей);
- виджет чата на чистом JS, подключается одним `<script>`;
- страница-журнал `/admin` со всеми сообщениями;
- SQLite для хранения диалогов.

## Требования

- Python 3.10 или новее
- интернет только для установки зависимостей

## Установка

Windows (PowerShell):

```
cd rayfund-bot
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Если PowerShell ругается на запрет выполнения скриптов, выполни `Set-ExecutionPolicy -Scope Process Bypass` и повтори активацию. В обычном cmd активация делается командой `.venv\Scripts\activate.bat`.

Linux / macOS:

```
cd rayfund-bot
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Если пакеты качаются слишком медленно, добавь зеркало: `pip install --default-timeout=120 --retries 10 -i https://mirrors.aliyun.com/pypi/simple/ -r requirements.txt`.

## Запуск

```
uvicorn app.main:app --reload
```

Сервис поднимется на `http://localhost:8000`. Остановка: `Ctrl+C`. Если порт занят, добавь `--port 8001` и подставляй его во все адреса ниже.

При первом запуске автоматически создаётся файл `chat.db` с историей сообщений. Чтобы очистить историю, останови сервис и удали этот файл.

## Что открыть для проверки

| Адрес | Что там |
|---|---|
| `http://localhost:8000/` | Страница-заглушка вместо сайта фонда, в правом нижнем углу кнопка чата |
| `http://localhost:8000/admin` | Журнал сообщений. Ключ по умолчанию `dev`, вводится в поле сверху, затем «Показать» |
| `http://localhost:8000/docs` | Swagger: можно вручную дёргать API из браузера |
| `http://localhost:8000/api/health` | Проверка, что сервис жив, и сколько загружено тем и фраз |

Удобнее всего открыть два окна рядом: чат и журнал. Журнал обновляется раз в 5 секунд, там видно, как каждое сообщение классифицировалось.

## Сценарии для тестирования

Напиши в чат и сравни результат:

| Сообщение | Ожидаемое поведение |
|---|---|
| заберёте котёнка | Тема `cannot_surrender_animal`, статус `answer` |
| как стать волонтёром | Тема `become_volunteer`, статус `answer` |
| реквизиты | Тема `bank_details`, статус `answer` |
| нашёл собаку на улице что делать | Тема `found_animal_what_to_do`, статус `answer` |
| сколько стоит стерилизация | Тема `program_sterilization`, статус `answer` |
| какая сегодня погода | Статус `fallback`, предложение написать на info@rayfund.ru |
| привет | Статус `suggest`: бот предлагает выбрать тему кнопками (известный недочёт, нет интента приветствия) |

Тексты ответов пока заглушки вида «[Ответ для темы ... ещё не заполнен]», потому что в `intents.yaml` поля `answer` помечены `TODO`. Это нормально: проверяется механика (определение темы, пороги, журнал), а не содержание.

Также проверь:

- нажатие на кнопку-подсказку («Возможно, вы имели в виду») отправляет выбранную тему и получает ответ;
- после 20 сообщений в минуту с одного IP приходит «Слишком много запросов»;
- после перезагрузки страницы чат запоминает сессию (в журнале сообщения остаются под тем же id сессии);
- на узком экране (режим мобильного устройства в DevTools) панель чата занимает почти всю ширину.

## API

`POST /api/chat`

Свободный текст:

```
{"session_id": "любая-строка-от-8-символов", "text": "как стать волонтёром"}
```

Выбор темы по кнопке:

```
{"session_id": "любая-строка-от-8-символов", "intent_id": "become_volunteer"}
```

Ответ:

```
{
  "status": "answer",
  "intent": "become_volunteer",
  "score": 1.0,
  "reply": "текст ответа",
  "url": "https://rayfund.ru/help/volunteer/",
  "escalate": false,
  "suggestions": []
}
```

Поля ответа:

- `status`: `answer` (уверенный ответ), `suggest` (средняя уверенность, в `suggestions` до 3 тем на выбор), `fallback` (ничего не найдено);
- `intent`: id найденной темы или `null`;
- `score`: близость к лучшей фразе, от 0 до 1;
- `url`: страница сайта с подробностями, если есть;
- `escalate`: стоит ли предложить связь с человеком.

Пример запроса из терминала Linux / macOS:

```
curl -X POST http://localhost:8000/api/chat -H "Content-Type: application/json" -d '{"session_id":"testsession1","text":"реквизиты"}'
```

На Windows проще пользоваться Swagger по адресу `/docs`, там же видны схемы запросов.

`GET /api/admin/messages?limit=200` возвращает последние сообщения. Нужен заголовок `X-Admin-Key`.

`GET /api/health` возвращает `{"ok": true, ...}`.

## Настройка

Всё настраивается переменными окружения, значения по умолчанию подходят для локального теста.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ADMIN_KEY` | `dev` | Ключ доступа к журналу |
| `CORS_ORIGINS` | `*` | Список разрешённых сайтов через запятую |
| `RATE_LIMIT` | `20` | Запросов в минуту с одного IP |
| `DB_PATH` | `chat.db` | Путь к файлу SQLite |
| `INTENTS_PATH` | `intents.yaml` | Путь к базе тем |
| `T_HIGH` | `0.5` | Порог уверенного ответа |
| `T_LOW` | `0.28` | Порог, ниже которого бот отвечает отказом |

Пример на Windows (PowerShell):

```
$env:ADMIN_KEY="свой_ключ"
$env:RATE_LIMIT="60"
uvicorn app.main:app --reload
```

Переменные действуют только в текущем окне терминала. Для cmd вместо `$env:ИМЯ="..."` используется `set ИМЯ=...`.

## База тем (`intents.yaml`)

Каждая тема описывается так:

```
- id: become_volunteer
  priority: normal
  url: https://rayfund.ru/help/volunteer/
  answer: Текст ответа, который увидит пользователь
  paraphrases:
    - "как стать волонтёром"
    - "хочу помогать руками"
```

Поля:

- `id`: уникальное имя темы;
- `paraphrases`: примеры формулировок вопроса; чем разнообразнее, тем лучше находит бот;
- `answer`: готовый ответ; пока `TODO`, тексты нужно взять с сайта или у команды фонда;
- `url`: ссылка «Подробнее на сайте» под ответом;
- `priority: critical`: для темы понижается порог срабатывания (используется там, где ошибка дорого стоит);
- `escalate: true`: под ответом появляется подсказка написать человеку.

Поле `static: true` в файле присутствует как пометка для будущей логики (реквизиты отдавать фиксированным блоком), в текущем прототипе оно ничего не делает.

После правки файла перезапусти сервис, база читается один раз при старте (с `--reload` перезапуск произойдёт сам для `.py`-файлов, но для YAML лучше перезапустить вручную).

Фразы из `paraphrases` нельзя использовать как тестовую выборку для замера точности, их писали для обучения поиска. Для оценки качества нужен отдельный набор вопросов, написанный людьми из команды.

## Подключение виджета к сайту

Добавь на страницу перед закрывающим `</body>`:

```
<script src="https://адрес-сервиса/static/widget.js" data-bottom="80" defer></script>
```

Для WordPress это можно сделать через плагин вроде WPCode (секция «Footer») или хук `wp_footer` в дочерней теме.

Необязательные атрибуты:

- `data-bottom`: отступ кнопки от нижнего края в пикселях (поднимает чат над липкими элементами сайта);
- `data-title`: заголовок окна чата;
- `data-api`: адрес API, если он отличается от адреса, откуда загружен скрипт.

Перед публикацией сервис нужно запускать по HTTPS, иначе браузер заблокирует запросы со страницы с HTTPS.

## Структура проекта

```
rayfund-bot/
  app/
    main.py        роуты, rate limit, CORS
    engine.py      поиск темы и сборка ответа
    db.py          работа с SQLite
  static/
    widget.js      виджет чата
    demo.html      страница-заглушка
    admin.html     журнал сообщений
  intents.yaml     база тем
  requirements.txt
```

Движок отделён от остального кода: `main.py` обращается только к `engine.respond(text)` и `engine.render(intent_id)`. Чтобы заменить поиск (например, на эмбеддинги), достаточно переписать `engine.py`, сохранив формат возвращаемого словаря.

## Что не доделано

- Тексты ответов (`answer`) не заполнены.
- Нет интента приветствия и общих фраз («спасибо», «пока»).
- Нет автотестов и замера точности на отдельной выборке.
- Нет контекста диалога: каждое сообщение обрабатывается независимо, поэтому уточняющие вопросы вида «а сколько это стоит?» не работают.
- Нет защиты журнала помимо одного ключа и нет экспорта.
- Нет Dockerfile и конфигурации для продакшена.

## Возможные проблемы

- **`ModuleNotFoundError: No module named 'app'`**: запускай команду из папки `rayfund-bot`, а не из `app`.
- **Чат не отвечает, в консоли браузера ошибка CORS**: задай `CORS_ORIGINS` с адресом страницы, на которой открыт виджет.
- **Журнал показывает «Неверный ключ»**: ключ должен совпадать с `ADMIN_KEY`; если переменная не задана, используется `dev`.
- **`429 Слишком много запросов`**: подожди минуту или увеличь `RATE_LIMIT`.
- **Порт 8000 занят**: запусти с `--port 8001`.
